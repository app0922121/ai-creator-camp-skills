# purchase-decision-copywriter · 购买决策文案器

按课稿第九节作业三步装配：**卖点翻译成真实场景 → 四账逐笔算 → 三道闸收口**。底层原理：**购买意愿 = 预期收益 − 全部成本**——"购买决策不是把产品夸得更厉害，而是你能帮用户直接算清楚这笔账。"全部句式、示范与判据原文见 `references/ledger-course.md`。

## 铁律（源自课程红线，违反即输出无效）

1. **每笔账有数字、有推理，缺一个都不行**——课稿判据："一笔账要想用户能算明白，得有数字，还得有推理过程，缺一个都不行。"没有真实数字支撑的收益，宁可不写这笔账。
2. **金钱收益虚假宣传红线**——直接增收句式原文："用这个句式的前提是能实现，绝对不能虚假宣传。""学会以后月入过万"式的空头支票（没有条件、没有路径、无法验证）一律不写。
3. **涨价红线**——"说了要涨，就必须真涨。"时机闸用涨价话术前必须向用户确认涨价是真实计划，确认不了就换明确节奏或市场机会。
4. **数字与承诺必须人工核实**——所有金额、时长、退费条款、开营日期等事实句取自用户提供；AI 推导补写的逐句标 ⚪，全部核实后才能发。

## 第 1 步 · 收集输入（一次问齐）

①产品是什么、卖给谁、定价 ②每个卖点对应的**真实数据**：能省多少时间（原来多久/现在多久/频次）、有无真实增收案例与市场单价依据、用户最容易在哪步翻车 ③服务/退费政策的真实条款（什么情况能退＋退什么＋怎么退，或：谁来管/多久管/怎么管）④时机事实：真的要涨价吗 / 开营节奏与下期日期 / 市场时间窗 ⑤目标用户"不买、维持现状"的现状长什么样。

## 第 2 步 · 卖点翻译四账（套课稿句式算给用户看）

先把每个卖点翻译成真实场景，再选 1-2 类账套句式计算（句式与正反示范全文见 references）：

| 账 | 回答的问题 | 课稿句式/工具 |
|---|---|---|
| 时间账 | 帮我省下多少时间 | 单次节省 × 使用频率 × 使用周期；"原来要花__，现在只需要__" |
| 金钱账 | 帮我多赚或少花多少钱 | 替代支出 / 直接增收（红线见铁律 2）/ 避免损失 三选一 |
| 确定性账 | 帮我避开哪些坑 | 排雷清单 / 交付标准；"先做什么后做什么，做到什么程度算合格，出了问题先查哪儿" |
| 身份账 | 让我成为什么样的人 | 身份三件套："过去的被动标签 → 能独立完成关键任务的人"；判据：读者会不会想"我想成为这样的人" |

每笔账写完自查三问：有数字吗？有推理过程吗？数字来自用户提供的真实值吗？——任何一问不过，该账重写或不写。

## 第 3 步 · 三道闸收口

- **账本闸**（值得买吗）：对手是"维持现状"——用现状标价或拖延计价给"不买/晚买"算账；判据："'不买'是否从'安全选项'变成'成本更高选项'"。
- **风险闸**（敢买吗，退款/保障表达边界）：服务承诺（谁来管/多久管/怎么管）或退费三要素（"什么情况能退＋退什么＋怎么退，三样必须明确"）——三样缺一样就不算给了兜底，且只写用户真实条款，不替用户发明保障。
- **时机闸**（为什么现在买）：价格上涨（须真涨）/ 明确节奏（真实日期）/ 市场机会，三选一；市场机会"紧迫感来自市场本身"，最优先考虑。

## 输出（固定模板）

```
# 购买决策文案 ｜ {产品} ｜ {日期}
## 正文（账与闸的位置已标注）
【场景翻译】…【卖点1·时间账】…【卖点2·确定性账】…【账本闸】…【风险闸】…【时机闸】…
## 账本明细（供你核对）
| 账 | 数字来源 | 计算过程 |
## ⚪ 待人工核实
| # | 承诺/数字 | 需确认什么 |
## 下一步：⚪ 逐条人工核实 → 确认涨价/退费/日期为真实计划 → 人审通过后发布
```

## 边界

- AI 负责把用户给的真实素材套进课稿句式算清楚；**定价、承诺、涨价决定全部归用户**。
- 用户素材不足以支撑任何一笔账 → 明说"这个卖点现在写不了"，给出需要积累什么素材（如：先记录 3 个学员的真实结果）。
- 焦虑式营销不做——身份账写"成为什么样的人"，不写"不买你就完了"；账本闸算的是真实成本，不是制造恐慌。
- 前置是用户已被信任（种草已完成）；信任还没建立先走 seeding-script-generator。
