# social-account-doctor-course · 拆账号验证判断 + 主页装修（课程版）

> Based on JuneYaooo/social-account-doctor (MIT)，上游许可全文见 `references/UPSTREAM-LICENSE`。
> 课程版核心改造：从「拆爆款」改为「拆账号」——不追单条钩子，用每个账号最近约 20 条内容验证你的账号假设，再把验证出的判断装修到自己主页上。课程原文判据见 `references/course-benchmark.md`（三类对标/五处拆解/四项判断）与 `references/course-homepage.md`（主页四件套）。

## 铁律（源自课程红线，违反即输出无效）

1. **账号数据必须真实喂入**（用户粘贴内容列表/截图/导出数据，或经用户同意用上游 tikhub CLI 抓取公开数据），**禁止 AI 凭账号名字想象内容**——课程红线：幻觉高发。没数据只给找号指引与收集清单，绝不开拆。
2. **数据不足时明说覆盖范围，不硬凑 20 条**——每个账号必须标注「实际取得 n 条 / 覆盖 xx 时间段 / 缺什么」。
3. **不要只看一条爆款，要看最近 20 条内容**——高频选题必须聚类（簇 + 占比），不是只点评最高赞那条。
4. **每条判断标三档**：事实（页面真实出现的信息）/ 推断（根据事实形成的判断）/ 未知（现有数据无法确认）。三档不混写，未知不硬答。
5. **对标不是抄爆款**——「这不是对标，这是跟风」。产出必须落到四项判断，不输出"照他改标题/改简介"式建议。
6. 简介与昵称中的资历、数字必须来自用户真实经历，AI 不虚构；报告语言面向非技术用户，不出现脚本名/接口名（继承上游规则 H6）。

## 第 0 步 · 收集数据（缺什么问什么，一次问齐）

每个对标账号需要五样：①主页文本或截图（昵称/简介/粉丝量/橱窗、链接等承接入口）②置顶内容 ③近约 20 条内容列表（标题 + 形式 + 互动数据）④代表性内容的评论区样本（高赞/高频问题，附原评论链接或截图编号）⑤可见变现痕迹。

- 用户还没有对标账号 → 先给「找 3 类对标」指引（references/course-benchmark.md 第二节）+ 头腰尾组合 + 上述五样收集清单，本次到此为止。
- 本机装有上游 social-account-doctor 的 tikhub CLI 时，可提议代抓公开数据（作品列表/评论）；接口失败不硬刚，回到用户粘贴。
- 开拆前逐账号登记数据覆盖：实际取得 n 条、时间跨度、缺失项——写进报告头部（继承上游 H3：半成品显式标注）。

## 第 1 步 · 三类对标归位

把每个账号归入：**直接对标**（服务对象和具体问题相似，验证人群和问题是否真有需求）/ **内容形式对标**（表达方式值得学，须确认拍摄形式自己能否实现）/ **变现路径对标**（收入方式相似，看日常怎么发内容、怎么引导成交）。不足 3 类明说缺哪类，并提醒头腰尾组合（1 头部看天花板 + 1 腰部看稳定打法 + 1 小而清晰看能否模仿起步）。

## 第 2 步 · 每个账号拆 5 处

按课程「拆对标账号的 5 个位置」逐处拆（原文判据见 references/course-benchmark.md 第三节）：

| 位置 | 拆什么 |
|---|---|
| ①昵称+简介 | 说清是谁/服务谁/解决什么/关注得到什么？ |
| ②置顶内容 | 想用什么内容建立第一印象？ |
| ③高频选题 | 近 20 条聚成 2-4 簇：条数占比 + 代表标题 + 互动相对水平 |
| ④评论区 | 用户真正关心什么 → 做需求聚类（见下） |
| ⑤变现 | 主页商业承接与引流途径（橱窗/课程/资料包/社群/咨询/商务合作） |

**④的需求聚类**（用户需求挖掘合并于此）：从代表性内容的评论区提取用户问题，每簇需求填六个字段——
具体场景 / 用户正在完成的任务 / 遇到的障碍 / 想要的结果 / 用户使用的原话（逐字引用）/ 原评论链接或截图编号。

## 第 3 步 · 四项判断（是"验证判断"，不是"验证结论"）

逐项下判断，每项必须引用第 2 步的具体证据（哪条内容/哪条评论），并标 事实/推断/未知：
①**是否存在需求信号**（评论区有没有真实用户在提问）②**用户关心哪些具体问题**（落到具体任务和场景，不停留在"AI 提效"这种大词）③**什么内容形式建立信任**（测评合集/真实工作流/前后对比/案例拆解/观点判断）④**是否观察到变现承接**（粉丝很多但没有任何变现痕迹 → 明示"谨慎对标"预警）。

## 第 4 步 · 主页装修四件套 + 模拟图

判断成立后，把它外化成自己的门头（原文判据见 references/course-homepage.md）：

- **昵称候选 3 版**：只用"名字 + 方向"或"身份 + 方向"两种结构，不抽象、不难搜。
- **三行简介 3 版**：第一行我是谁 / 第二行我帮谁解决什么问题 / 第三行我用什么方式提供什么结果，逐行对应不写成散文。
- **三条置顶内容**：置顶 1 我是谁、为什么做这个账号；置顶 2 我怎么解决一个典型问题；置顶 3 一个结果型内容（工具清单/流程模板/方法判断）。给标题级描述。
- **前 10 条内容栏目**：围绕 2-3 个固定栏目，超过 3 个即违规；每栏目给名称 + 服务的问题 + 示例选题。
- **主页示意图**：用户拍板后，读 `assets/homepage-mockup-template.html`，按模板头部注释替换占位符，生成抖音版（深色）或小红书版（浅色）单文件 HTML。只用本模板，不安装 html-anything、归藏卡片等外部工具；示意图仅版式预览，不模仿平台真实 UI 与品牌标识。

## 输出格式（固定模板）

```
# 对标验证与主页装修 ｜ {我的定位一句话} ｜ {日期}
## 数据覆盖
| 账号 | 对标类型 | 实际取得 | 覆盖时间段 | 缺失项 |
## 账号拆解（每个账号一节）
### @{账号名}（直接/内容形式/变现路径 ｜ 头部/腰部/小而清晰）
{五处拆解表} + {需求聚类表（六字段）}
## 四项判断（验证判断）
| 判断 | 结论 | 证据（哪条内容/哪条评论） | 事实/推断/未知 |
⚠ 预警（如触发）：粉丝多但无变现痕迹等
## 主页装修四件套
昵称 3 版 ｜ 简介 3 版（各三行） ｜ 置顶 3 条 ｜ 前 10 条栏目
→ 拍板后生成主页示意图（抖音版 / 小红书版）
```

## 边界

- AI 做拆解、聚类与判断整理；**学不学这个号、四件套选哪版，归用户拍板**。
- 一次多个账号 → 逐个拆，最后补一张横向对照表，不合并成模糊的"行业印象"。
- 拆单条爆款找钩子/仿写 → 上游 social-account-doctor（crack/adapt）；自己账号的发布数据诊断 → sm-diagnose。
