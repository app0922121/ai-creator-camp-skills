# tutorial-script-sixgrid · 教程脚本六格初稿器（第五课）

把创作者亲手做过一遍的真实 AI 任务，按「复现六格」（结果承诺 / 输入材料 / 关键步骤 / 判断标准 / 失败修正 / 可拿走资产）写成教程脚本初稿，并派生一件粉丝可拿走的资产（提示词 / 输入模板 / 操作清单）。方法论完整取自课程第五节，六格逐字原文、周报完整示范与拍摄提醒见 `references/six-grid.md`（成稿前通读，第 2、3、5 步逐节对照使用）。

## 铁律（源自课程红线，违反即输出无效）

1. **真实任务记录是强制输入，无记录不生成**——课程四问红线："我自己真的做成过吗？……你至少要完整做过一遍，知道哪一步最容易出错，什么结果看起来不错但其实不能用。"用户拿不出记录 → 不代写脚本，改为输出「先去做一遍」任务清单（做什么、留哪些记录），做完再来。
2. **结果先行**——成稿前必须补完「我准备帮助谁，在什么场景下，用 AI 完成什么具体结果？」。"'学会使用 AI'不是结果。'一段简历描述'才是用户能够看见、能够判断有没有完成的结果。"
3. **事实句只能来自用户记录**——数字、效果、前后对比、翻车细节一律取自记录；AI 推导补写的示范句逐句标 ⚪ 待人工核实，不混入正文冒充事实。
4. **前后对比要公平**——"不要为了让 AI 显得特别厉害，故意把原来的结果做得很差。也不要用不同资料生成两个结果，却告诉用户只是因为换了一句提示词。""真实，永远比'看起来很厉害'更重要。"
5. **可拿走资产必须经人亲测可复现后才随内容发布**——AI 派生的资产只是草稿，输出时强制附亲测提醒。

## 第 1 步 · 收集输入

缺什么问什么，一次问齐：

① 任务定义句三要素：帮谁 / 什么场景 / 完成什么具体结果 ② **真实任务记录**：每一步做了什么、输入了什么（提示词与材料）、得到什么、哪里翻车了、怎么修正的 ③ 工具环境：模型 / 版本 / 插件 / 参数（课程要求"如果你的教程使用了特定模型、版本、插件或者参数，也要在这里简短说明"）④ 可展示素材：整理前后的对比物、第一次失败结果的截图。

② 给不出 → 触发铁律 1，停。

## 第 2 步 · 四问预检

逐问核对（原文见 references 第二节），任何一问答不出即记一票：

1. 这是目标用户真的会遇到的任务吗？（"不要为了展示 AI 很厉害，发明一个用户平时根本不会做的任务。"）
2. 我自己真的做成过吗？
3. 结果能不能被展示和判断？
4. 用户看完以后，能不能完成一个小结果？——切到**最小可复现结果**："不能小到没有价值，也不能大到一条内容根本讲不清楚。"

"四个问题里，如果有两个你答不上来，这条内容先不要急着拍。"→ 停止成稿，建议缩小任务、重新测试，或换一个更熟悉的题目。

## 第 3 步 · 六格逐格成稿

按六格顺序成稿，每格的写法判据与周报完整示范见 `references/six-grid.md` 第三、四节：

| 格 | 这一格要做到 | 素材来源 |
|---|---|---|
| ①结果承诺 | 开头见结果，不自我介绍、不讲工具背景 | 前后对比素材 |
| ②输入材料 | 说清要准备什么＋模型/版本/参数 | 记录＋工具环境 |
| ③关键步骤 | 只讲"会改变结果的动作"，不念按钮 | 记录的每步输入输出 |
| ④判断标准 | 给 1-3 个检查标准 | 记录中"怎么判断能用" |
| ⑤失败修正 | 说清根据什么问题、修改什么信息 | 翻车点与修正过程 |
| ⑥可拿走资产 | 交付马上能用的东西 | 第 4 步派生 |

第⑤格禁语："我们不能只说'多试几次'或者'换一个提示词'"——修正必须具体到"根据什么问题，修改什么信息"。

## 第 4 步 · 派生可拿走资产

从记录里提炼一件资产：提示词 / 输入模板（表）/ 操作清单，三选一按任务性质定。资产要能让用户"填完交给 AI，成功率比裸问高"——"它不是为了让用户多收藏一份资料，而是降低他真正开始行动的门槛。"输出时附一行加粗提醒：**发布前请亲自用这份资产从零跑一遍，确认可复现**（铁律 5）。

## 第 5 步 · 视频化顺序与画面清单

按课程给定顺序把六格排成可拍结构："先展示结果，再点出常见失败；接着说明要准备的材料；然后演示三到五个关键步骤；生成以后，带用户检查结果；最后补一个失败修正，再交付模板或者清单。"

同时生成画面清单，五类齐全（作业第五步）：**原始材料、操作过程、第一次结果、修正过程、最终结果**。

三个拍摄提醒写进脚本备注（原文见 references 第八节）：① 只展示真正影响结果的画面（登录、等待、鼠标移动都压缩）② **提示词不要一闪而过**——"关键句要放大、停留，或者拆成字幕，让用户知道这一句解决的是什么问题" ③ 前后对比要公平（铁律 4）。

结尾行动引导：邀请用户完成任务后回来说卡在哪一步——"评论区里出现的新问题，又会成为你下一批真实选题。"

## 第 6 步 · 输出脚本卡（固定模板）

```
# 教程脚本 ｜ {选题} ｜ {日期}
**任务定义句**：我准备帮助{谁}，在{场景}下，用 AI 完成{具体结果}。
**工具环境**：{模型/版本/插件/参数}
## 四问预检
| 问 | 答（答不出两问 → 本卡不产出脚本） |
## 六格脚本
### ①结果承诺 …（每格正文；⚪ 标注 AI 补写待核实句）
### ②输入材料 … ③关键步骤 … ④判断标准 … ⑤失败修正 … ⑥可拿走资产
## 画面清单
| # | 画面 | 类型（原始材料/操作过程/第一次结果/修正过程/最终结果） |
## 可拿走资产（全文）
{提示词/输入表/清单本体}
**发布前请亲自用这份资产从零跑一遍，确认可复现。**
## 人工核实清单
| # | 位置 | 待核实内容（数字/效果/对比） |
```

## 边界

- AI 做的是结构化成稿与资产派生；**事实归用户**——记录里没有的，AI 不编，宁可留空问。
- 产出对齐课程作业的"三样东西"：一条可以直接录制的教程脚本、一份对应的画面清单、一个可以交付给用户的模板或检查表。
- 用户想教"自己没做成过"的题 → 回到铁律 1，给最小任务建议，做完再来。
- 测评/横评类内容（"哪个产品该选谁"）不在此写 → review-test-orchestrator。
