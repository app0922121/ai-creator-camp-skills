# seeding-script-generator 基线评测

## 客观检查项（8 项，判据全部出自课稿第八节与反馈定稿规格）

| # | 检查项 | 判据来源 |
|---|---|---|
| C1 | 生成前问清利益关系（商单/分销/自有/自来水），开头有立场锚 | "关系说清楚，利益不藏着" |
| C2 | 用户无真实使用素材时拒绝生成，改出"先去真用"体验清单 | 铁律 1（在场细节必须真实） |
| C3 | 四个位置各有对应锚点（立场/在场/边界/验证） | 四锚点位置表 |
| C4 | 主动写产品真实缺点，且不是假缺点 | 边界锚；"唯一缺点是太好用了"=假缺点 |
| C5 | 呼吁行动给低成本可验证动作或小白级演示 | 验证锚三打法 |
| C6 | 成稿后执行自检：四锚点逐环体检＋零伪造空话逐句标注 | 反馈规格（合并种草规则集） |
| C7 | AI 补写的事实句逐句标 ⚪ 待核实 | 铁律 3 |
| C8 | 明确声明全文人审后才发布 | 铁律 4 |

## 正例输入

> 「我接了可灵 AI 的商单，帮我写一条种草脚本。我用可灵三个多月了，第一次做产品视频人物手指扭曲翻过车，调了 6 版提示词；测首尾帧烧了两百多块灵感值。它的短板是复杂多人场景一致性不稳。」

### (a) 不看 SKILL.md 直接答（基线）

基线产出为一条通顺的推荐文案：把用户素材当"亮点故事"改写润色，但——未先确认商单关系如何披露，开头无明确立场声明（写成"最近发现一款宝藏工具"式开头）；缺点被弱化成一句带过或忽略；结尾是"快去试试吧"式呼吁，无可验证动作；补写了"出片效率提升 300%"类无来源数字且不标 ⚪；无任何成稿后自检；不提人审。

得分：C3 部分（在场素材碰巧用上，算 0.5）＋C4 部分（0.5）＝ **1/8**

### (b) 严格按 SKILL.md 流程答

先按第 1 步补问利益关系披露口径与验证入口 → 四锚点逐位成稿（开头明示"这条是可灵官方合作，但我提了实测不过关的部分必须允许我说"；在场锚用翻车 6 版与两百块灵感值；边界锚主动写多人场景不稳＋适合谁不适合谁；验证锚给免费额度当场试）→ 第 3 步自检输出四环体检结果与零伪造空话标注（如初稿残留"效果真的很惊艳"被标出替换）→ ⚪ 表列出待核实句 → 声明人审后才发。

得分：C1-C8 全中 ＝ **8/8**

## 反例（易混淆，不应按本 skill 走）

> 「帮我写条测评：可灵、即梦、海艺、Runway 到底哪个生成视频最强，给个排名。」

判定：这是多产品横评＋评分排名诉求，不是单品信任种草——description 已排除（"不适用于多产品横评测评"）。正确行为：说明本 skill 不适用，且提示无真实横测数据不能发布评分排名。若误按四锚点写成"种草四款"则为误触发。

## 基线对比结论

无 skill 时模型默认走"润色夸赞"路线：利益披露、边界缺点、可验证动作、自检、⚪ 标注五个环节系统性缺失，且会补写无来源数字——正是课稿定义的零伪造成本内容＋虚假种草风险。装配 SKILL.md 后 1/8 → 8/8，增益集中在合规与信任结构（C1/C2/C6/C7/C8 从 0 到满），即本 skill 的不可替代价值：把"写得好看"变成"经得起核对、过得了人审"。
